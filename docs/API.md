# API Reference

Base URL (dev): `http://127.0.0.1:8000`
Interactive docs (auto-generated by FastAPI): `/docs`

## Endpoints

### `GET /`
Basic app info.

### `GET /health`
```json
{"status": "ok", "version": "1.0.0-phase1", "models_loaded": true, "database_ok": true}
```

### `POST /api/v1/analyze/sms`
Request:
```json
{"message": "URGENT! Verify your OTP now...", "sender": "+1234567890"}
```
Response: full `AnalysisReport` (see below).

### `POST /api/v1/analyze/url`
Request:
```json
{"url": "http://paypa1-secure-login.top/signin"}
```
Response: full `AnalysisReport`.

### `GET /api/v1/analysis/{analysis_id}`
Returns a previously stored report. 404 if `STORE_ANALYSIS=false` was set
at analysis time (results aren't persisted by default — this is expected,
not a bug).

### `POST /api/v1/feedback`
```json
{"analysis_id": "abc123", "label": "FALSE_POSITIVE", "comment": "This was my bank"}
```
Stored for human review only — never auto-retrains production models.

### `GET /api/v1/model-info`
Returns active model names/versions/types for SMS and URL, plus risk
engine and feature versions.

### `GET /api/v1/statistics`
Aggregate dashboard statistics (total scans, verdict breakdown, category
breakdown, feedback counts).

### `GET /api/v1/threat-intelligence/status`
Which threat-intel sources are enabled/disabled right now.

## Error handling

- `422` — validation error (empty/oversized input, malformed URL)
- `429` — rate limit exceeded
- `413` — request body too large
- `500` — internal error (generic message returned, full detail logged server-side, never leaked to the client)
